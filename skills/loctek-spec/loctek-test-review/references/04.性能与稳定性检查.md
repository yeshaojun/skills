# 性能与稳定性检查

> 📌 **分类逻辑**：性能、可靠性、可观测性都是关于**系统在生产环境中的健康度**，统归一处。性能保证快，可靠性保证不挂，可观测性保证出问题能定位。

## 一、后端性能检查矩阵

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| PERF-001 | **N+1查询** | 循环内是否有逐条DB查询（应改为批量查询） | 100条数据→101次DB请求，接口超时 | P0 |
| PERF-002 | **大结果集** | `selectList`是否无条件查询全表数据（缺WHERE/LIMIT） | 数十万条数据加载到内存→OOM | P0 |
| PERF-003 | **缺失索引** | WHERE/JOIN 条件字段是否有索引 | 全表扫描→慢查询→数据库CPU飙高 | P0 |
| PERF-004 | **循环内RPC** | 循环内是否有同步RPC/HTTP调用（应批量或异步） | N次网络往返→接口耗时线性增长 | P0 |
| PERF-005 | **未分页查询** | 列表类接口是否有分页参数（page/pageSize） | 前端一次加载全部数据→页面卡死 | P1 |
| PERF-006 | **大事务** | @Transactional 范围是否过大（包含了RPC/MQ发送） | 事务持锁时间过长→DB连接池耗尽 | P1 |
| PERF-007 | **缓存策略缺失** | 高频读低频写的数据是否使用了缓存 | 每次请求都查DB→不必要的负载 | P1 |
| PERF-008 | **缓存穿透/雪崩** | 缓存key设计是否有防穿透措施（空值缓存/布隆过滤） | 恶意请求直打DB | P1 |
| PERF-009 | **序列化性能** | 是否在热路径上使用了低效序列化（如XML而非JSON） | 接口响应时间增加 | P2 |
| PERF-010 | **线程池配置** | 自定义线程池参数（核心数/队列/拒绝策略）是否合理 | 线程耗尽→请求堆积→服务不可用 | P1 |
| PERF-011 | **连接池配置** | DB/Redis/HTTP连接池大小是否合理 | 连接耗尽→新请求无法获取连接 | P1 |
| PERF-012 | **深分页** | 分页查询是否使用了`OFFSET`+`LIMIT`的深分页 | offset很大时性能急剧下降 | P1 |

## 二、前端性能检查矩阵

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| FPERF-001 | **大数据渲染** | 长列表是否使用了虚拟滚动（Virtual Scroll） | 1000+条DOM→页面卡顿 | P1 |
| FPERF-002 | **频繁重渲染** | 组件是否有不必要的 re-render（缺少memo/shouldComponentUpdate） | 性能浪费→页面卡顿 | P1 |
| FPERF-003 | **大文件/大图** | 是否对图片做了懒加载和压缩 | 首屏加载时间过长 | P2 |
| FPERF-004 | **定时器泄漏** | setInterval/setTimeout 是否在组件卸载时清除 | 内存泄漏→页面越用越卡 | P1 |
| FPERF-005 | **高频事件节流** | scroll/resize/input 事件是否做了 debounce/throttle | 每帧触发回调→页面卡死 | P1 |
| FPERF-006 | **打包体积** | 是否按需引入组件库（tree-shaking），避免全量引入 | 首屏JS包过大→白屏时间长 | P2 |

## 三、后端可靠性与容错检查矩阵

> 系统在异常情况下能否**自愈**而不是**崩溃**。

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| REL-001 | **超时设置** | HTTP/RPC/DB/Redis 调用是否设置了超时时间 | 下游挂了→线程耗尽→服务雪崩 | P0 |
| REL-002 | **熔断机制** | 调用下游频繁失败时，是否有熔断（Hystrix/Sentinel/Resilience4j） | 下游故障拖垮上游 | P0 |
| REL-003 | **降级策略** | 非核心依赖不可用时，是否有降级方案 | 非核心功能故障影响核心链路 | P0 |
| REL-004 | **重试策略** | 重试是否有次数限制、退避策略、幂等保证 | 无限重试→下游被打爆 | P0 |
| REL-005 | **限流保护** | 核心接口是否有限流（QPS/并发数限制） | 突发流量打垮服务 | P1 |
| REL-006 | **优雅停机** | 应用关闭时是否等待请求处理完成再停止 | 强制停机→请求被中断→数据不一致 | P1 |
| REL-007 | **健康检查** | 是否暴露了健康检查端点（/health） | K8s无法感知服务不健康 | P1 |
| REL-008 | **故障隔离** | 不同业务模块的线程池/连接池是否独立（舱壁模式） | A模块的慢查询耗尽B模块的连接 | P1 |
| REL-009 | **兜底返回** | 服务异常时是否返回友好提示而非堆栈信息 | 堆栈信息暴露→安全风险 | P1 |
| REL-010 | **依赖降级开关** | 核心依赖是否可通过配置开关快速关闭/切换 | 线上问题无法快速止血 | P1 |

## 四、前端可靠性检查矩阵

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| FREL-001 | **全局错误捕获** | 是否有全局的 ErrorBoundary/onError 捕获未处理异常 | JS报错→整个页面白屏 | P0 |
| FREL-002 | **网络异常处理** | 断网/弱网时是否有提示和重试机制 | 无提示→用户以为操作成功 | P0 |
| FREL-003 | **接口超时** | HTTP请求是否设置了超时时间 | 无限等待→页面一直loading | P1 |
| FREL-004 | **离线降级** | 核心数据是否有本地缓存/离线方案 | 断网后APP完全不可用 | P2 |

## 五、后端可观测性检查矩阵

> 线上出问题时，能否**快速定位**是决定MTTR（平均恢复时间）的关键。

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| OBS-001 | **入口日志** | 接口入口是否记录了请求参数（脱敏后） | 线上问题无法复现 | P0 |
| OBS-002 | **出口日志** | 调用下游（RPC/DB/MQ）是否记录了耗时和结果 | 无法判断慢在哪一环 | P0 |
| OBS-003 | **异常日志** | catch 块内是否记录了完整的异常堆栈（而非仅message） | 只有message无法定位到具体行 | P0 |
| OBS-004 | **链路追踪** | 是否传递了 traceId/spanId（跨服务调用） | 多服务场景下无法串联调用链 | P1 |
| OBS-005 | **埋点/Metrics** | 核心业务指标是否有打点 | 无法通过监控面板观察业务健康度 | P1 |
| OBS-006 | **告警规则** | 关键异常是否触发了告警 | 线上异常无人知→故障扩散 | P1 |
| OBS-007 | **日志级别合理性** | 正常流程INFO，异常ERROR（不是WARN） | 全是ERROR→告警疲劳 | P2 |
| OBS-008 | **结构化日志** | 日志是否使用结构化格式（JSON/KV） | 非结构化→grep困难 | P2 |

## 六、前端可观测性检查矩阵

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| FOBS-001 | **JS异常上报** | 是否接入了前端异常监控（Sentry/Fundebug/自建） | JS报错用户无感→问题积累 | P0 |
| FOBS-002 | **接口异常上报** | 接口4xx/5xx是否自动上报 | 后端异常前端没感知 | P1 |
| FOBS-003 | **性能指标采集** | 是否采集了FCP/LCP/FID等Web Vitals | 页面变慢无法感知 | P2 |
| FOBS-004 | **用户行为埋点** | 关键操作路径是否有埋点 | 无法分析功能使用率和转化率 | P2 |

## 七、性能走查产出格式

```markdown
### [性能/可靠性走查] {类名/文件名}

| 走查点ID | 所在行 | 检查维度 | 发现问题 | 风险等级 | 改进建议 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| PERF-001 | L67 | N+1查询 | 循环内逐条调用selectById | 🔴 高 | 改为selectBatchIds批量查询 |
| REL-001 | L23 | 超时设置 | RPC调用未设置超时 | 🔴 高 | 增加@DubboReference(timeout=3000) |
| OBS-003 | L89 | 异常日志 | catch块只log.error(e.getMessage()) | 🟡 中 | 改为log.error("msg", e) 保留堆栈 |
```
