# 代码模式专属检查维度

## 概述

本文档定义了代码潜在缺陷检查（Step 4）中遇到特定代码模式时**自动激活**的额外检查项。

> 🎯 **定位说明**：Job/MQ/延迟消息/DB 操作不是独立的白盒测试类型。按业界标准，白盒测试分为**静态分析**（代码走查/审查）和**动态分析**（单元测试/覆盖率验证）。这些代码模式只是走查时遇到特定代码类型后，需要额外关注的检查维度。

### 何时激活？

| 代码模式 | 激活条件 | 检查维度数 |
| :--- | :--- | :--- |
| Job/定时任务/批处理 | 扫描到 `@Scheduled`、`*Job*.java`、XXL-Job handler | 12 项 + 5 走查点 |
| MQ/消息消费 | 扫描到 `*Consumer*.java`、`*Listener*.java`、`@KafkaListener`、`@RocketMQMessageListener` | 12 项 + 5 走查点 |
| 延迟消息 | 扫描到 `setDelay`、`scheduledMessage`、延迟投递相关代码 | 3 项 |
| DB持久层 | 扫描到 `*Mapper*.java`、`*Repository*.java`、`@Transactional` | 10 项 |

## 一、Job/定时任务/批处理

### 1.1 检查场景矩阵

| 场景ID | 检查场景 | 验证目标 | 构造条件 | 预期行为 | 优先级 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| JOB-001 | **空数据防空转** | 第一批查无数据时立刻退出 | DB中无可处理数据 | Job 执行后立刻 return/break，不进入死循环 | P0 |
| JOB-002 | **单条数据处理** | 仅1条待处理数据时正常 | DB中恰好1条待处理 | 正常处理完毕，状态更新正确 | P1 |
| JOB-003 | **满批次处理** | 恰好等于 pageSize 时继续翻页 | DB中数据量=pageSize | 处理完后继续查询下一批（而非误判为最后一批） | P0 |
| JOB-004 | **超批次分批处理** | 数据量 > pageSize 时正确分批 | DB中数据量 = pageSize × 3 + 5 | 正确分4批处理，最后1批处理5条 | P0 |
| JOB-005 | **游标推进安全** | 每批偏移量正确递增 | 多批次数据 | 批次间 offset 正确递增 pageSize，不遗漏不重复 | P0 |
| JOB-006 | **单条失败隔离** | 循环内某条失败不影响其他 | 第3条数据处理时抛异常 | 第1、2、4、5条正常处理完成；第3条记录错误日志 | P0 |
| JOB-007 | **全部失败** | 所有数据都处理失败 | Mock 所有处理逻辑抛异常 | Job 正常结束（不卡死不崩溃），所有失败都有日志 | P1 |
| JOB-008 | **中断安全退出** | 收到 interrupt 时安全停止 | 处理过程中发送 interrupt 信号 | 完成当前批次后安全退出，已处理数据不丢失 | P1 |
| JOB-009 | **并发防重（分布式锁）** | 两个实例不同时执行 | 两个 Job 实例同时启动 | 仅1个获取锁执行，另1个跳过或等待 | P0 |
| JOB-010 | **超时保护** | 单批处理时间过长 | Mock 某条数据处理耗时很长 | 有超时机制，超时后跳过或记录告警 | P1 |
| JOB-011 | **幂等性验证** | Job 重复执行不产生重复数据 | Job 执行完后立刻再执行一次 | 第二次执行无新数据产生 | P0 |
| JOB-012 | **日志完整性** | 每批处理有摘要日志 | 正常多批次处理 | 每批有开始/结束日志，包含批次号、处理条数、耗时 | P2 |

### 1.2 走查特有维度

走查到 Job 代码时，除通用维度（一~八）外，额外检查：

| 走查点 | 检查内容 | 典型风险 |
| :--- | :--- | :--- |
| 翻页逻辑 | offset 递增还是 lastId 递增 | offset 大数据量性能差 |
| 退出条件 | `resultSize < pageSize` 还是 `resultSize == 0` | 恰好 pageSize 时提前停止 |
| 异常隔离 | try-catch 在循环内还是循环外 | 循环外则一条失败全批中断 |
| 状态更新 | 处理后状态 A→B，查询条件是否排除 B | 否则重复处理 |
| 锁机制 | 是否有分布式锁 / DB 行锁 | 无锁则多实例并发冲突 |

### 1.3 退出条件典型缺陷

```java
// ❌ 退出条件不安全：恰好 pageSize 条时会提前退出
while (true) {
    List<Record> records = mapper.selectPage(offset, pageSize);
    if (records.size() < pageSize) {  // 恰好 100 条时也会退出！
        break;
    }
    process(records);
    offset += pageSize;
}

// ✅ 正确写法
while (true) {
    List<Record> records = mapper.selectPage(offset, pageSize);
    if (CollectionUtils.isEmpty(records)) {
        break;
    }
    process(records);
    offset += pageSize;
    if (records.size() < pageSize) {
        break;  // 最后一批不满页，确认处理完后再退出
    }
}
```

## 二、MQ/消息消费

### 2.1 检查场景矩阵

| 场景ID | 检查场景 | 验证目标 | 构造条件 | 预期行为 | 优先级 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| MQ-001 | **正常消费** | 合法消息正常处理 | 发送标准格式消息 | 消息被正确消费并处理 | P0 |
| MQ-002 | **消息格式异常** | JSON 解析失败优雅处理 | 发送非 JSON 格式消息 | 不抛未捕获异常，记录 ERROR 日志，不无限重试 | P0 |
| MQ-003 | **必填字段缺失** | 关键字段 null/空 | JSON 中缺少必填字段 | 记录 WARN 日志，跳过处理 | P0 |
| MQ-004 | **消费幂等-重复消息** | 同一消息重复消费 | 同一 msgId 发送两次 | 第二次跳过，不产生重复数据 | P0 |
| MQ-005 | **消费幂等-业务去重** | 相同业务数据重复 | 不同 msgId 但相同业务数据 | 通过业务唯一键去重 | P1 |
| MQ-006 | **消费超时** | 处理耗时过长 | Mock 业务处理耗时 > 超时时间 | 超时重试或转死信，不永久阻塞 | P1 |
| MQ-007 | **消费失败重试** | 业务异常触发重试 | Mock 抛 RuntimeException | 按策略重试 N 次后停止 | P1 |
| MQ-008 | **死信队列** | 超过最大重试次数 | 持续消费失败超过 maxRetry | 进入死信队列 | P1 |
| MQ-009 | **消息顺序性** | 依赖顺序的消息 | 发送 A→B→C 状态变更链 | 按序处理，乱序时有等待或拒绝机制 | P2 |
| MQ-010 | **消费者宕机恢复** | 重启后恢复消费 | 消费者宕机重启 | 未 ack 的消息重新投递 | P1 |
| MQ-011 | **大消息体** | 消息体极大 | 超大 JSON | 不 OOM，正常处理或拒绝 | P2 |
| MQ-012 | **下游异常隔离** | 消费中下游服务异常 | Mock 下游 RPC 抛异常 | 消费失败但正确处理（重试/死信） | P0 |

### 2.2 走查特有维度

走查到 MQ 消费代码时，额外检查：

| 走查点 | 检查内容 | 典型风险 |
| :--- | :--- | :--- |
| 反序列化 | JSON 解析是否在 try-catch 中 | 未 catch 则格式异常无限重试 |
| 幂等标识 | 用什么做幂等（msgId/业务ID/Redis锁） | 无幂等则重复消费会重复执行 |
| 事务边界 | DB 操作和 ack 的事务关系 | 先 ack 后 DB 则 DB 失败会丢数据 |
| 异常分类 | 哪些异常要重试，哪些直接丢弃 | 格式错误不应重试，业务异常可重试 |
| 线程模型 | 单线程还是多线程消费 | 多线程需注意顺序性和并发安全 |

### 2.3 幂等实现典型缺陷

```java
// ❌ 无幂等保护
@RocketMQMessageListener(topic = "chat-guide-topic")
public void onMessage(Message message) {
    ChatGuideDTO dto = JSON.parseObject(message.getBody(), ChatGuideDTO.class);
    guideService.execute(dto);  // 重复消费会重复执行
}

// ✅ 正确写法：基于 msgId + Redis 去重
@RocketMQMessageListener(topic = "chat-guide-topic")
public void onMessage(Message message) {
    String msgId = message.getMsgId();
    if (!redisTemplate.opsForValue().setIfAbsent("mq:dedup:" + msgId, "1", 24, TimeUnit.HOURS)) {
        log.info("消息重复消费跳过, msgId={}", msgId);
        return;
    }
    try {
        ChatGuideDTO dto = JSON.parseObject(message.getBody(), ChatGuideDTO.class);
        guideService.execute(dto);
    } catch (JSONException e) {
        log.error("消息格式异常，不重试, msgId={}", msgId, e);
        // 不抛异常，避免无限重试格式错误的消息
    }
}
```

## 四、DB 持久层

### 4.1 检查场景矩阵

| 场景ID | 检查场景 | 验证要点 |
| :--- | :--- | :--- |
| DB-001 | INSERT 唯一性 | 是否有唯一索引防止重复插入 |
| DB-002 | UPDATE 乐观锁 | 并发更新是否用 version 字段防覆盖 |
| DB-003 | UPDATE 条件充分 | WHERE 条件是否精确，不会误更新其他记录 |
| DB-004 | DELETE 软删除 | 是否使用逻辑删除而非物理删除 |
| DB-005 | 批量操作大小 | 批量 INSERT/UPDATE 是否有分批（避免超过 DB 限制） |
| DB-006 | 事务范围 | @Transactional 是否覆盖了需要原子性的操作 |
| DB-007 | 事务传播 | 嵌套事务的传播行为是否正确 |
| DB-008 | 索引命中 | 查询 SQL 的 WHERE 条件是否命中索引 |
| DB-009 | 分页查询 | 大数据量分页是否使用游标分页而非 OFFSET |
| DB-010 | NULL 值处理 | 新增字段是否设置 DEFAULT 值，查询是否处理 NULL |
