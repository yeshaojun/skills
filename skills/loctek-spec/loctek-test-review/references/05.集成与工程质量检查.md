# 集成与工程质量检查

> 📌 **分类逻辑**：本文档关注系统**集成交互**（API/数据流/配置）和**代码工程质量**（回归/异常传播/可维护性/国际化），都是保障系统长期健康运行的基础。

## 一、API契约检查矩阵

> 适用于微服务架构场景，前后端分离或服务间调用时必检。

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| API-001 | **入参类型一致** | 接口文档定义的参数类型与代码实际接收类型是否一致 | 前端传String后端期望Long→异常 | P0 |
| API-002 | **必填参数校验** | @NotNull/@NotBlank/@Valid 注解是否完整 | 缺少校验→空指针 | P0 |
| API-003 | **返回值结构** | 接口返回的JSON结构是否与文档/前端使用一致 | 前端取不到字段→页面空白 | P0 |
| API-004 | **错误码规范** | 业务异常是否返回了规范的错误码和提示信息 | 前端拿到500→用户看到"系统异常" | P1 |
| API-005 | **版本兼容** | 接口字段变更是否做了向后兼容 | 旧版APP调用新接口→崩溃 | P1 |
| API-006 | **接口幂等** | POST接口是否支持幂等（如创建订单重复提交） | 重复创建数据 | P0 |
| API-007 | **响应时间** | 接口是否有SLA要求，代码逻辑能否满足 | 超时→前端loading过久 | P1 |

## 二、数据流与状态一致性检查矩阵

> 关注数据从产生到消费的全链路一致性。

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| DF-001 | **数据一致性** | DB操作和缓存操作是否在同一事务内（或有补偿机制） | DB写了缓存没更新→读到脏数据 | P0 |
| DF-002 | **最终一致性** | 异步操作（MQ/Job）失败后是否有重试/补偿机制 | 消息丢失→数据永久不一致 | P0 |
| DF-003 | **状态机完整性** | 业务状态流转是否覆盖了所有合法路径和非法路径 | 非法状态变更→业务数据错乱 | P0 |
| DF-004 | **时序依赖** | 多个异步操作之间是否有时序依赖 | 先执行了后续步骤→逻辑错误 | P1 |
| DF-005 | **数据精度** | 金额/比例计算是否使用了BigDecimal而非double/float | 浮点精度丢失→金额差异 | P0 |
| DF-006 | **时区处理** | 时间存储/展示是否统一处理了时区 | 跨时区用户看到错误时间 | P1 |
| DF-007 | **并发写安全** | 同一数据的并发写入是否有乐观锁/分布式锁保护 | 并发覆盖→数据丢失 | P0 |

## 三、配置与环境风险检查矩阵

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| CFG-001 | **环境差异** | 配置是否区分了dev/test/prod环境 | 测试环境连了生产数据库 | P0 |
| CFG-002 | **配置缺失兜底** | 读取配置时是否有默认值兜底 | 配置中心故障→空指针 | P1 |
| CFG-003 | **开关/灰度** | 新功能是否通过功能开关控制 | 上线出问题无法快速止血 | P1 |
| CFG-004 | **超时配置** | HTTP/RPC/DB 超时时间是否合理配置 | 下游故障→线程挂死→雪崩 | P0 |
| CFG-005 | **日志级别** | 生产环境日志级别是否为INFO（非DEBUG） | 日志写满磁盘→服务不可用 | P1 |

## 四、回归风险评估检查矩阵

> 代码变更是否可能**破坏现有功能**。

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| REG-001 | **公共方法签名变更** | 被多处调用的公共方法签名是否变更 | 修改了签名→所有调用方都受影响 | P0 |
| REG-002 | **数据库Schema变更** | 新增/修改/删除字段是否影响现有查询和映射 | 字段名改了→旧SQL爆错 | P0 |
| REG-003 | **配置变更影响** | 新增/修改配置项是否对现有逻辑产生影响 | 默认值变了→老逻辑行为改变 | P1 |
| REG-004 | **枚举值新增** | 新增枚举值后所有switch/if判断是否覆盖了新值 | 新值走default→静默跳过 | P0 |
| REG-005 | **接口返回值变更** | 接口返回新增/删除/改名字段是否影响前端 | 前端取不到字段→页面异常 | P0 |
| REG-006 | **依赖升级影响** | 升级第三方依赖是否有破坏性变更 | API不兼容→编译通过但运行报错 | P1 |
| REG-007 | **删除/废弃代码** | 删除的类/方法是否还有其他地方在调用 | 运行时ClassNotFoundException | P0 |
| REG-008 | **MQ Topic/消息结构变更** | Topic改名或消息体字段变更是否同步通知了消费者 | 消费者解析失败→消息堆积 | P0 |

## 五、异常传播链检查矩阵

> 错误从底层到上层的传播路径是否正确。

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| EXC-001 | **异常分类** | 是否区分了业务异常和系统异常 | 业务异常被当系统异常→不必要的告警 | P1 |
| EXC-002 | **异常包装** | 底层异常是否正确包装传递（保留原始cause） | 丢失原始异常→无法定位根因 | P0 |
| EXC-003 | **全局异常处理** | 是否有 @ControllerAdvice 统一处理异常 | 未捕获异常→返回500+堆栈信息 | P0 |
| EXC-004 | **异常转换** | Service层异常是否正确转换为HTTP状态码 | 所有异常都返回500→前端无法区分 | P1 |
| EXC-005 | **事务异常** | @Transactional中异常是否正确触发回滚 | checked exception默认不回滚→数据不一致 | P0 |
| EXC-006 | **异步异常** | 异步线程/CompletableFuture中异常是否被捕获 | 异步异常静默丢失→问题无人知 | P1 |

## 六、可维护性评估检查矩阵

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| MAINT-001 | **方法复杂度** | 单个方法行数 > 80行 或 圈复杂度 > 10 | 过于复杂→难以理解→容易引入Bug | P1 |
| MAINT-002 | **参数过多** | 方法参数 > 5个（应封装为DTO） | 调用方容易传错参数顺序 | P2 |
| MAINT-003 | **魔法数字/字符串** | 是否有硬编码的数字/字符串而非常量/枚举 | 修改时遗漏某处→行为不一致 | P2 |
| MAINT-004 | **代码重复** | 是否有大段重复代码（应抽取为公共方法） | 修一处忘改另一处→Bug | P2 |
| MAINT-005 | **命名规范** | 类名/方法名/变量名是否表达了其职责 | 命名不清→阅读代码需要猜测 | P2 |
| MAINT-006 | **注释完整性** | 复杂业务逻辑是否有注释说明"为什么这样做" | 没有注释→维护者不敢改 | P2 |
| MAINT-007 | **耦合度** | Service之间是否循环依赖 | 修改一处牵动全局→回归风险高 | P1 |
| MAINT-008 | **配置外置** | 业务参数是否硬编码在代码中 | 修改参数需要重新部署 | P1 |

## 七、国际化与编码检查矩阵

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| I18N-001 | **硬编码文案** | 用户可见文案是否硬编码在代码中 | 多语言切换无法生效 | P1 |
| I18N-002 | **日期格式** | 日期展示是否考虑了用户时区 | 跨时区用户看到错误时间 | P1 |
| I18N-003 | **字符编码** | 文件读写/HTTP传输/DB存储是否统一使用UTF-8 | 中文乱码 | P0 |
| I18N-004 | **数字/货币格式** | 金额展示是否考虑了千分位、小数位数 | 金额展示不符合当地习惯 | P2 |
| I18N-005 | **排序规则** | 中文排序是否使用了Collator | 排序结果不符合预期 | P2 |
