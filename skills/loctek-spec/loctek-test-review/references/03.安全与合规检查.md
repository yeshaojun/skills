# 安全与合规检查

> 📌 **分类逻辑**：安全和合规都是关于**保护用户和数据**的维度，统归一处。安全防攻击，合规防处罚。

## 一、后端安全检查矩阵

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| SEC-001 | **SQL注入** | SQL拼接是否使用了`${}` 或字符串拼接而非`#{}` / PreparedStatement | 攻击者可篡改/删除数据库数据 | P0 |
| SEC-002 | **XSS防御** | 用户输入是否在展示前做了转义/编码 | 攻击者可在页面注入恶意脚本 | P0 |
| SEC-003 | **越权访问** | 接口是否校验了当前用户对数据的操作权限（水平越权+垂直越权） | 用户A可操作用户B的数据 | P0 |
| SEC-004 | **敏感数据暴露** | 接口返回值是否包含了不必要的敏感信息（手机号/身份证/密码hash） | 信息泄露 | P0 |
| SEC-005 | **硬编码密钥/密码** | 代码中是否有硬编码的数据库密码、API Key、Secret | 密钥泄露到Git仓库 | P0 |
| SEC-006 | **CSRF防护** | 状态变更接口（POST/PUT/DELETE）是否有CSRF Token校验 | 攻击者可伪造请求 | P1 |
| SEC-007 | **文件上传验证** | 文件上传是否校验了文件类型、大小、内容（非仅后缀名） | 上传恶意文件执行代码 | P1 |
| SEC-008 | **日志脱敏** | 日志中是否打印了敏感信息（密码、Token、完整手机号） | 日志泄露导致信息泄露 | P1 |
| SEC-009 | **接口限流** | 关键接口（登录/注册/发送验证码）是否有频率限制 | 暴力破解/短信轰炸 | P1 |
| SEC-010 | **依赖漏洞** | pom.xml/package.json中的第三方依赖是否有已知漏洞（CVE） | 利用已知漏洞攻击 | P2 |
| SEC-011 | **反序列化安全** | 是否使用了不安全的反序列化（如ObjectInputStream/fastjson） | 远程代码执行 | P1 |
| SEC-012 | **加密算法强度** | 是否使用了弱加密算法（MD5/DES/SHA1用于密码存储） | 密码被破解 | P1 |

## 二、前端安全检查矩阵

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| FSEC-001 | **XSS防御** | 动态内容渲染是否使用了`v-html`/`dangerouslySetInnerHTML`（不安全） | 注入恶意脚本 | P0 |
| FSEC-002 | **敏感信息存储** | Token/用户信息是否存储在localStorage而非httpOnly Cookie | Token被XSS窃取 | P0 |
| FSEC-003 | **接口权限透传** | 请求是否携带了认证信息（Token），前端是否有401拦截跳转 | 未授权访问 | P1 |
| FSEC-004 | **URL参数注入** | 路由参数/query参数是否做了校验和转义 | 页面劫持/钓鱼 | P1 |
| FSEC-005 | **敏感数据展示** | 手机号/身份证/银行卡是否做了脱敏展示（如`138****8888`） | 信息泄露 | P1 |
| FSEC-006 | **console清理** | 生产环境是否清理了console.log中的敏感数据 | 调试信息泄露 | P2 |

## 三、合规性检查矩阵

> 数据保护法规（如GDPR、个保法）要求对用户数据的处理必须合规。

| 场景ID | 检查场景 | 检查要点 | 典型风险 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| COMP-001 | **数据最小化** | 是否只采集/存储了业务必需的用户数据 | 过度采集→违规 | P1 |
| COMP-002 | **数据保留期限** | 用户数据是否有自动清理/归档机制 | 永久保留→存储成本+合规风险 | P1 |
| COMP-003 | **审计日志** | 敏感操作（删除/修改/导出用户数据）是否有操作日志 | 无法证明合规操作 | P1 |
| COMP-004 | **数据导出/删除** | 是否支持用户数据的导出和删除（GDPR权利） | 不支持→违反GDPR/个保法 | P1 |
| COMP-005 | **用户授权** | 数据使用是否在用户授权范围内 | 超范围使用→违规 | P0 |

## 四、安全走查产出格式

```markdown
### [安全走查] {类名/文件名}

| 走查点ID | 所在行 | 安全维度 | 发现问题 | 风险等级 | 改进建议 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| SEC-001 | L45 | SQL注入 | 使用了${}拼接SQL参数 | 🔴 高 | 改为#{}参数化 |
| COMP-003 | L12 | 审计日志 | 删除用户数据无操作日志 | 🟡 中 | 增加审计日志记录 |
```
