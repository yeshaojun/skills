# 代码走查维度与检查清单

## 概述

代码走查是白盒测试的基础环节，目标是通过逐段精读代码，识别需求规约下的逻辑缺陷和潜在风险。本文档定义了 **8 大走查维度**，共 8 个维度。每个维度包含具体的检查要点和典型缺陷示例。

---

## 维度一：卫语句完整性 (Guard Clause)

### 检查要点

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | 入参 null 检查 | 方法的每个引用类型入参是否有 null 判断 |
| 2 | 集合空判断 | List/Set/Map 类型参数是否在遍历前判空（`isEmpty()` 或 `CollectionUtils.isEmpty()`） |
| 3 | 字符串空白判断 | String 类型是否用 `StringUtils.isBlank()` 而非仅 `!= null` |
| 4 | 业务前置校验 | 是否验证了业务前提条件（如"先有合同才能建群"） |
| 5 | 提前返回 | 不满足条件时是否 `return / throw` 提前退出，避免深层嵌套 |

### 典型缺陷示例

```java
// ❌ 缺少卫语句
public void processChat(String tenantId) {
    Tenant tenant = tenantService.getById(tenantId); // tenantId 可能为 null
    List<Group> groups = tenant.getGroups(); // tenant 可能为 null → NPE
    for (Group g : groups) { // groups 可能为 null → NPE
        // ...
    }
}

// ✅ 正确写法
public void processChat(String tenantId) {
    if (StringUtils.isBlank(tenantId)) {
        log.warn("tenantId为空，跳过处理");
        return;
    }
    Tenant tenant = tenantService.getById(tenantId);
    if (tenant == null) {
        log.warn("租客不存在, tenantId={}", tenantId);
        return;
    }
    List<Group> groups = tenant.getGroups();
    if (CollectionUtils.isEmpty(groups)) {
        // 执行无群聊逻辑
    }
}
```

## 维度二：条件逻辑正确性

### 检查要点

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | 比较运算符 | `>` vs `>=`、`<` vs `<=` 是否与需求一致 |
| 2 | 逻辑运算符 | `&&` vs `||` 是否符合业务"且/或"语义 |
| 3 | 等值比较 | 字符串用 `equals()` 而非 `==`；枚举用 `==` 而非 `equals()` |
| 4 | 否定条件 | `!condition` 是否正确，特别是复杂条件的否定（德摩根定律） |
| 5 | 条件顺序 | 短路特性：`obj != null && obj.method()` 的顺序是否正确 |

### 典型缺陷示例

```java
// ❌ PRD 规定"引导次数超过3次则取消"，代码写成了 >=3
if (guideCount >= 3) {  // 应该是 > 3，第3次还应该引导
    cancelGuide();
}

// ❌ 字符串用 == 比较
if (status == "ACTIVE") {  // 应该用 .equals()
    // ...
}
```

## 维度三：枚举值覆盖完整性

### 检查要点

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | switch 覆盖 | 所有枚举值是否都有对应的 case |
| 2 | default 兜底 | switch 是否有 default 分支处理未知枚举值 |
| 3 | 新增枚举 | 本次需求新增的枚举值是否在所有相关 switch 中添加了处理 |
| 4 | if-else 链 | 类似 switch 的 if-else if 链是否有 else 兜底 |

### 典型缺陷示例

```java
// ❌ 新增了 PRIVATE_CHAT 类型但 switch 中没有处理
switch (serviceObjectType) {
    case GROUP_CHAT:
        handleGroupChat();
        break;
    // 缺少 case PRIVATE_CHAT: → 静默逃逸
    default:
        log.error("未知的服务对象类型: {}", serviceObjectType);
}
```

## 维度四：异常处理合理性

### 检查要点

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | catch 粒度 | 是否过于宽泛（catch Exception/Throwable），应细化到具体异常 |
| 2 | 异常吞没 | catch 块中是否仅 log 而不抛出或返回，导致调用方无法感知失败 |
| 3 | finally 执行 | 资源释放是否放在 finally 中（或使用 try-with-resources） |
| 4 | 异常信息 | log 中是否包含足够的上下文信息（入参值、业务ID等） |
| 5 | 循环体内 catch | 循环中某条记录异常是否阻断了其余记录的处理 |

### 典型缺陷示例

```java
// ❌ catch 过于宽泛且吞没异常
try {
    sendGroupMessage(tenantId, message);
} catch (Exception e) {
    log.error("发送失败");  // 缺少异常对象和上下文
    // 没有 throw 或返回错误标记，调用方认为发送成功
}

// ✅ 正确写法
try {
    sendGroupMessage(tenantId, message);
} catch (MessageSendException e) {
    log.error("群聊消息发送失败, tenantId={}, message={}", tenantId, message, e);
    throw new BusinessException("消息发送失败", e);
}
```

## 维度五：日志可观测性

### 检查要点

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | 关键分支日志 | 每个 if/else 分支入口是否有 INFO 级别日志 |
| 2 | 异常日志 | catch 块中是否有 WARN/ERROR 日志且包含异常堆栈 |
| 3 | 入口出口日志 | 核心方法的入参和返回值是否有日志记录 |
| 4 | 业务ID关联 | 日志是否包含可追踪的业务ID（sessionId、tenantId等） |
| 5 | 日志级别正确 | 正常流程用 INFO，异常用 WARN/ERROR，调试用 DEBUG |

## 维度六：幂等防御

### 检查要点

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | 重复调用安全 | 同一请求多次调用是否产生重复数据（如重复插入） |
| 2 | 唯一性约束 | INSERT 操作是否有数据库唯一索引保护 |
| 3 | 状态前置检查 | 更新状态前是否检查当前状态是否允许变更 |
| 4 | MQ 消费幂等 | 消息重复消费是否有去重机制（如 msgId 去重表） |

---

## 维度七：线程安全

### 检查要点

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | 共享变量 | 是否存在非线程安全的共享变量（如 SimpleDateFormat） |
| 2 | 并发修改 | 多线程同时修改同一集合是否使用 ConcurrentHashMap 等线程安全容器 |
| 3 | 分布式锁 | 多实例部署场景下是否有分布式锁保护临界区 |
| 4 | 原子操作 | 先查后改的操作是否有 CAS 或乐观锁保护 |

---

## 维度八：资源泄漏

### 检查要点

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | DB 连接 | 手动获取的数据库连接是否在 finally 中关闭 |
| 2 | IO 流 | InputStream/OutputStream/Reader/Writer 是否正确关闭 |
| 3 | 锁释放 | ReentrantLock 的 unlock 是否在 finally 中 |
| 4 | 线程池 | 临时创建的线程池是否有 shutdown 机制 |

## 前后端走查维度对照

> 🎯 **核心原则**：先确认代码端类型（后端/前端/全栈），再选择对应的走查维度。

### 适用范围

| 维度 | 后端（Java/Go/Python） | 前端（Vue/React/小程序） |
| :--- | :--- | :--- |
| 维度一：卫语句 | ✅ null/空集合 | ✅ undefined/null/空数组 |
| 维度二：条件逻辑 | ✅ equals/== | ✅ ===/类型转换 |
| 维度三：枚举覆盖 | ✅ switch/case | ✅ 状态映射/条件渲染 |
| 维度四：异常处理 | ✅ try-catch | ✅ Promise.catch/接口异常 |
| 维度五：日志可观测 | ✅ 服务端日志 | ⚠️ 部分适用（埋点/console） |
| 维度六：幂等防御 | ✅ 重复插入/消费 | ✅ 防连点/重复提交 |
| 维度七：线程安全 | ✅ 并发/锁 | ❌ 不适用（单线程） |
| 维度八：资源泄漏 | ✅ 连接/IO | ✅ 定时器/事件监听 |
| **前端维度A：接口交互** | ❌ 不适用 | ✅ 前端专属 |
| **前端维度B：状态管理** | ❌ 不适用 | ✅ 前端专属 |
| **前端维度C：数据格式化** | ❌ 不适用 | ✅ 前端专属 |
| **前端维度D：交互体验** | ❌ 不适用 | ✅ 前端专属 |
| **前端维度E：兼容性** | ❌ 不适用 | ✅ 前端专属 |

## 前端专属走查维度

> 以下维度仅在走查前端代码（Vue/React/Angular/小程序/H5）时使用。

### 前端维度A：接口交互 (API Interaction)

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | 接口异常处理 | 每个 API 调用是否有 `.catch()` 或 `try-catch`，出错时是否有用户提示 |
| 2 | 加载态处理 | 请求中是否有 loading 状态，防止用户误操作 |
| 3 | 空数据展示 | 接口返回空数组/null 时，页面是否有"暂无数据"兜底展示 |
| 4 | 超时/断网处理 | 网络超时或断网时是否有友好提示和重试机制 |
| 5 | 接口入参校验 | 前端是否在发送请求前校验了必填参数，避免发送无效请求 |

```javascript
// ❌ 缺少异常处理和 loading 态
async function loadData() {
  const res = await api.getList(); // 如果失败直接崩溃
  this.list = res.data; // res.data 可能是 null
}

// ✅ 正确写法
async function loadData() {
  this.loading = true;
  try {
    const res = await api.getList();
    this.list = res?.data ?? [];
  } catch (err) {
    this.$message.error('加载失败，请重试');
  } finally {
    this.loading = false;
  }
}
```

### 前端维度B：状态管理 (State Management)

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | 状态初始化 | 组件状态是否有合理的初始值（避免 undefined 导致渲染异常） |
| 2 | 状态同步 | 父子/跨组件状态是否同步更新，是否存在"数据不一致"的窗口期 |
| 3 | 页面切换 | 离开页面时是否清理了临时状态（定时器、轮询、WebSocket） |

### 前端维度C：数据格式化与展示 (Data Formatting)

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | 时间格式 | 后端返回的时间戳是否正确格式化（如 `YYYY-MM-DD HH:mm:ss`） |
| 2 | 金额格式 | 金额是否保留正确位数，是否有千位分隔符 |
| 3 | 枚举/状态映射 | 后端返回的状态码（如 `1/2/3`）是否正确映射为中文标签 |
| 4 | 文本截断 | 超长文本是否有截断处理（省略号），悬浮是否显示完整内容 |
| 5 | 空值展示 | 字段为空/null 时应显示什么（`--`、`暂无`、隐藏整行） |

### 前端维度D：交互体验 (User Interaction)

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | 按钮防连点 | 提交类按钮是否有 loading/disabled 防重复点击 |
| 2 | 表单校验 | 必填项是否有前端校验提示，格式（手机号/邮箱）是否正确 |
| 3 | 确认弹窗 | 危险操作（删除/关闭/提交）是否有二次确认弹窗 |
| 4 | 权限控制 | 按钮/菜单是否根据用户角色做了权限显隐控制 |

### 前端维度E：兼容性 (Compatibility)

| # | 检查项 | 说明 |
| :--- | :--- | :--- |
| 1 | 浏览器兼容 | 是否使用了目标浏览器不支持的 API（如 IE 不支持 `Promise`） |
| 2 | 响应式布局 | 不同屏幕尺寸下布局是否正常（特别是移动端） |
| 3 | 可选链兼容 | `obj?.property` 语法是否在目标环境中支持 |
