# 需求分析报告模板与四趟提取规则

## 输入获取

- 本地文档（.md/.docx/.pdf）与 wiki 链接至少提供一个。
- Wiki/网页链接：必须获取完整内容（滚动到底/翻页），嵌套链接全部打开读取；网络错误、权限受限、加载失败时明确报告，不得静默跳过。
- 有 `.changes/issues/` 时：issue 的验收标准/测试计划字段就是已结构化的需求条目，直接并入 Pass 1 的功能面，不必重复拆解。

## 分层多趟提取（禁止一次性输出所有内容）

### Pass 1: 功能面 (Function Surface)
- 功能点清单：功能模块 + 子功能 + 操作入口。
- 业务实体与状态机：业务对象（Entity）、核心字段、状态流转图（前置状态、触发事件、后置状态、操作权限）。
- 测试价值：直接转化为状态迁移用例。
- 同时提取"本期交付功能 / 测试排除项 / 重点测试项"，排除项防止多测。

### Pass 2: 规则面 (Rule Surface)
- 字段约束表：

  | 所属实体 | 字段名 | 数据类型 | 长度 | 必填 | 枚举值/正则 | 唯一性 | 需求来源 |
  |---|---|---|---|---|---|---|---|
  | Order | amount | Decimal | 10,2 | Y | > 0 | N | REQ-2.1 |

- 隐性规则：需求未明示但逻辑推导出的约束，必须标注【推导】。
- 测试价值：等价类与边界值的直接数据源。

### Pass 3: 依赖面 (Dependency Surface)
- 上游：谁调用我？入参校验重点。
- 下游：我调用谁？接口契约（Path、Method、核心参数）。
- 数据兼容规则：存量数据处理（历史脏数据兼容）、新旧版本并行。
- 测试价值：界定回归范围与 Mock 策略。

### Pass 4: 异常面 (Exception Surface)
- 业务异常：非法操作、状态冲突、权限不足。
- 系统异常：超时、降级、熔断、幂等。
- 边缘场景：空值、极值、并发锁冲突。
- 非功能性需求：性能（RT/QPS）、安全（越权）、数据一致性。
- 测试数据生成：来源、规则、构造方式，以及数据与链路影响（存量清洗、MQ 依赖等）。

## 约束条件

1. **源约束**：不知道就闭嘴。未在文档中明确提及或无法逻辑推导的内容严禁写入正文，只能出现在"风险与缺口"章节。
2. **编号绑定**：每个测试点（功能、规则、异常）必须绑定 REQ-* 编号；REQ-ID 的来源位置必须能在原文中精确定位，禁止编造。
3. **无幻觉**：禁止"通常""一般来说"等通用词汇，必须基于文档事实。
4. **目录驱动**：先输出文档层级目录，逐项标记是否完成提取，确保无遗漏。
