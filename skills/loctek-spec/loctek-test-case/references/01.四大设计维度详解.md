## 一、测试设计方法维度（核心骨架）

> 共 16 种方法按优先级分三层，每次设计前按层级依次评估选用。**禁止仅用场景法覆盖一切**，必须在用例标注中显式说明所用方法。

### 🔴 第一层：核心必用方法（每个需求必须评估是否适用）

| 设计方法 | 核心思想 | 适用场景 | 典型举例 |
| :--- | :--- | :--- | :--- |
| **等价类划分** | 将输入域划分为有效/无效等价类，每类取代表值 | 输入字段有值域范围 | 金额字段：有效类（1~99999）、无效类（<0、>99999、非数字） |
| **边界值分析** | 在等价类基础上重点测试边界及边界两侧 | 数值、字符数、时间等存在明确边界 | 最大字符数 100：测试 99、100、101；时间点：23:59、00:00、00:01 |
| **状态迁移法** | 对象的所有状态及合法/非法状态转换路径 | 业务对象有明确生命周期状态机 | 订单：待处理→处理中→已完成→已关闭；非法：已关闭→重新打开 |
| **场景法（E2E）** | 串联多个步骤模拟真实用户完整使用路径 | 完整业务链路、多步骤正向流程 | 发起聊天→业主回复→规则命中→订单建立→订单列表展示 |
| **错误推测法** | 基于经验主动猜测系统可能的失效点 | 边界遗漏、历史高频 Bug 区域 | 空串、null、特殊字符、并发双击、快速切换 Tab |

---

### 🟡 第二层：重要补充方法（按需求类型有选择地使用）

| 设计方法 | 核心思想 | 适用场景 | 典型举例 |
| :--- | :--- | :--- | :--- |
| **判定表法** | 列出所有条件组合与对应动作，穷举决策 | 多条件组合（AND/OR）决策，条件数 ≤4 | 权限A=有+权限B=有+商品=有→显示按钮；其他组合→不显示 |
| **因果图法** | 图形化建立输入（因）与输出（果）的关系网 | 多个输入条件高度联动且存在互斥关系 | 筛选项A选中则B置灰、C可选；B选中则A和C均不可用 |
| **两两组合法（Pairwise）** | 确保任意两个参数之间至少有一次组合出现 | 参数多（≥4）导致全量组合爆炸，条件独立性强 | 5个筛选项各有3~5个取值，全量3000+组合→Pairwise精简到25条 |
| **分类树法** | 将所有输入参数按维度先分类成树，再系统取叶子节点组合 | 输入参数多且分类维度清晰的表单/接口测试 | 将「地区/类型/时间/状态」四维度建树，再取各分支组合生成用例 |
| **正交表法** | 利用正交拉丁方设计，用最少用例覆盖最多因素组合 | 参数组合量爆炸但各参数间有交互效应 | 4因素各3水平→正交表L9仅需9条代替81条全组合 |
| **基于风险的测试（RBT）** | 根据功能业务风险等级优先分配测试资源 | 时间紧迫时决策「先测什么」 | 核心支付流程风险=高→全量覆盖；边缘展示逻辑风险=低→抽样验证 |
| **用户旅程图法** | 从真实用户使用路径出发识别所有触点与决策点 | 多角色、多入口、跨模块的复杂交互产品 | 用户从「进线→语音导航→群聊→提交订单→查询进度」的完整旅程 |

---

### 🟢 第三层：辅助手段（针对特定场景补充使用）

| 设计方法 | 核心思想 | 适用场景 | 典型举例 |
| :--- | :--- | :--- | :--- |
| **决策树法** | 将多层嵌套的 if-else 分支图形化为树状结构 | 分支逻辑多层嵌套、判定表难以展开时 | "有合同?→有群?→有订单?" 三层 Yes/No 树形展开 |
| **契约测试** | 验证服务提供方与消费方之间的接口协议一致性 | 微服务架构下多团队接口联调 | 接口字段名/类型/枚举值与调用方约定一致 |
| **模糊测试（Fuzz）** | 向系统输入大量随机、畸形或超长数据 | 接口安全性验证、输入框鲁棒性 | 输入10000字符、二进制数据、SQL注入字符串，观察是否崩溃 |
| **探索性测试框架** | 规范化记录探索测试路径 | 新功能上线前的自由探索补漏 | 测试人员自由探索功能，用「测试宪章」记录路径，事后固化为回归用例 |

## 二、业务功能维度（主体覆盖）

> 以下 6 类分支每类至少一条用例，禁止仅覆盖正向主流程。

### 正向主流程 `🏷️ 黑盒-正向`
- **定义**：从合法数据与正确操作出发，走通核心业务价值链路的完整路径
- **判定标准**：用例执行完毕后，主业务目标已实现（如订单已建立并落库）

### 正向分支流程 `🏷️ 黑盒-正向`
- **定义**：流程图中每一个判断节点（Yes/No）的独立分支路径，必须各自独立成一条用例
- **判定标准**：用例数量 ≥ 流程图判断节点总数

### 异常/错误流程 `🏷️ 黑盒-异常`
- **定义**：系统接收到错误输入或遭遇系统级异常时，能够正确捕获并给出合理响应
- **判定标准**：验证了错误提示文案、响应码，且系统未产生脏数据

### 数据一致性场景 `🏷️ 黑盒-一致性测试`
- **定义**：操作完成后，数据在各端（UI/DB/缓存/下游系统）保持一致
- **判定标准**：验证了 UI 展示值 = DB 落库值 = 下游收到的数据值

### 📌 操作按钮点击覆盖强制规则
PRD/Wiki 中明确提到的每一个操作按钮（含链接、图标操作、操作列入口），均必须生成对应点击用例。

| 用例类型 | 描述 | 标签 |
| :--- | :--- | :--- |
| **正向点击** | 有权限、数据状态合法时点击，验证按钮触发的业务动作 | `🏷️ 黑盒-正向` |
| **权限拦截** | 无对应操作权限时，按钮不渲染或点击被拦截（403） | `🏷️ 黑盒-安全防护` |
| **状态异常点击** | 对象处于不可操作状态时点击，系统给出明确提示而非报500 | `🏷️ 黑盒-异常` |

示例：PRD「操作列」有「详情、编辑、调整记录、删除」4个按钮，至少需生成 4×3=12 条操作类用例。

> ⚠️ 防遗漏检查：用例生成完毕后，回到 PRD 逐字扫描所有出现动词/按钮名称的句子，与已生成用例做 1:1 比对。

## 三、测试类型维度（专项领域）

> 与业务功能维度的分工：本节专注业务功能维度**未涵盖**的专项领域，在需求涉及时独立生成专项用例。

### 🔴 领域一：安全测试（Security Testing）

**触发条件**：需求涉及用户数据隔离、多用户体系、敏感数据展示、鉴权逻辑变更

| 测试方向 | 具体说明 | 验证要点 |
| :--- | :--- | :--- |
| **横向越权** | A 用户访问 B 用户的私有数据 | 接口返回 403/404，数据不可见 |
| **纵向越权** | 普通用户调用管理员级别接口 | 接口返回 403，操作不执行 |
| **URL 枚举攻击** | 直接拼接他人资源 ID 访问 | 系统正确拦截，不因 ID 可枚举而暴露数据 |
| **Token 伪造/篡改** | 手动修改 JWT payload 后发起请求 | 鉴权失败，返回 401 |
| **SQL 注入** | 输入框中注入 `' OR 1=1--` | 系统转义处理，不执行恶意 SQL |
| **XSS 攻击** | 输入 `<script>alert(1)</script>` | 转义存储，展示时不执行脚本 |
| **CSRF 防护** | 伪造跨站请求 | 系统拒绝无效 CSRF Token 的请求 |
| **敏感数据脱敏** | 查看手机号、身份证、银行卡等 | 展示时部分脱敏（如 138****8888） |
| **账号状态异常** | 已被封禁账号发起请求 | 返回 403，提示「账号已被禁用」 |
| **跨用户隔离** | A 用户账号访问 B 用户资源 | 数据隔离，返回 403 或 404 |

---

### 🟡 领域二：性能测试（Performance Testing）

**触发条件**：需求涉及高频写操作、批量处理、高并发入口、核心链路接口改造

| 测试方向 | 具体说明 | 验证要点 |
| :--- | :--- | :--- |
| **接口响应时间** | 单次请求正常负载下的耗时 | P99 响应时间 ≤ SLA 要求（通常 ≤ 500ms） |
| **按钮防抖/防重** | 前端快速多次点击提交按钮 | 请求只发出一次，不重复提交 |
| **接口幂等性** | 相同请求连续发送 N 次 | 数据库中只产生一条记录，无重复副作用 |
| **多端并发写** | A、B 同时对同一条记录发起修改 | 后提交方收到冲突提示，数据不被静默覆盖 |
| **高并发事务完整性** | 高频并发写入时的数据完整性 | 不产生脏数据、半截数据，事务有效 |
| **大数据量列表** | 分页列表含 100 万条数据时的响应 | 分页、搜索正常响应，不超时崩溃 |
| **批量操作性能** | 批量导出/导入大量数据 | 完成时间符合预期，内存不溢出 |

---

### 🟠 领域三：可靠性测试（Reliability Testing）

**触发条件**：需求依赖第三方服务、异步任务、消息队列，或涉及核心写操作的幂等/事务保障

| 测试方向 | 具体说明 | 验证要点 |
| :--- | :--- | :--- |
| **下游服务超时降级** | 依赖的第三方接口 5s 内未响应 | 前端有 loading，超时后提示「网络异常」 |
| **下游服务 500 降级** | 依赖的服务返回 500 错误 | 系统走降级逻辑，不将 500 直接透传给用户 |
| **服务熔断** | 下游服务持续不可用触发熔断 | 熔断器开启后快速失败，不堆积请求 |
| **消息重试与幂等** | MQ 消息消费失败后重试 | 按策略重试，超限后进入死信队列；重复消费不产生重复副作用 |
| **网络重传导致重复提交** | 前端超时后自动重试，服务端收到 2 次相同请求 | 接口幂等保障，DB 不产生重复记录 |
| **Token 过期自动续期** | 登录态超过有效期 | 自动跳转登录页，或静默续期 |
| **事务回滚** | 多步操作中途失败 | 数据库事务回滚，不产生半截脏数据 |

---

### 🟢 领域四：兼容性测试（Compatibility Testing）

**触发条件**：需求在存量数据/旧版本逻辑上叠加新规则，或存在多版本并行运行

| 测试方向 | 具体说明 | 验证要点 |
| :--- | :--- | :--- |
| **历史数据渲染兼容** | 旧版数据在新版 UI 下的展示 | 存量数据展示不报错、不乱码、不展示「undefined」 |
| **新老逻辑数据路由** | 新旧数据分别走不同处理逻辑 | 老版数据走老逻辑，新版数据走新逻辑 |
| **旧版入口下线兼容** | 旧版功能入口在新版被移除 | 旧入口不再展示，不产生 404/500 |
| **字段新增的默认值兼容** | 新增了 DB 字段，历史记录该字段为 null | 历史记录的新字段有合理默认值 |
| **接口版本兼容** | 接口升级后老版本客户端仍在使用 | 老版 API 调用不报错，或有明确的版本迁移引导 |

---

### 🔷 领域五：易用性测试（Usability Testing）

**触发条件**：需求涉及新增 UI 页面、表单、错误提示、空态展示、操作引导流程

| 测试方向 | 具体说明 | 验证要点 |
| :--- | :--- | :--- |
| **错误提示文案准确** | 操作失败时给出的提示 | 文案与 PRD 原文一致，包含失败原因和操作引导 |
| **空态展示** | 列表查询结果为 0 条 | 展示空态提示文案，不展示「undefined」或空白 |
| **Loading 状态** | 请求进行中时的等待状态 | 有 loading 遮罩，完成后消失 |
| **操作反馈即时性** | 用户操作后系统的响应速度 | 操作后立即有视觉/交互反馈（成功弹窗/状态更新等） |
| **边界数据的展示截断** | 超长文本在 UI 中的展示 | 省略号截断，不撑破布局 |

**主动 Hover 推断规则**（不得等待 PRD 明确写出「hover」才触发，应主动检测）：满足以下任一条件，必须主动生成至少 1 条 hover 探测用例（标注 `⚠️ 待确认 hover 是否实现`）：
- PRD 描述了超长文本/省略号截断相关表述
- 需求分析报告中标记了含 tooltip/气泡卡片/悬浮提示的字段
- 列表页中存在「名称」「描述」「备注」等通常可能超长的文本列

已明确 hover 时：必须生成独立 3 条验证：① hover 触发后完整内容可见；② 移开鼠标后提示消失；③ 内容与数据源一致。

---

### 🟤 领域六：UI 测试（UI Testing）

**触发条件**：需求涉及全新高保真交互组件落地、大规模样式迭代、前端布局重构

| 测试方向 | 具体说明 | 验证要点 |
| :--- | :--- | :--- |
| **布局与分辨率适配** | 页面在 1080P/大屏下的展示 | 无意外横向滚动条，内容不被截断 |
| **浏览器兼容渲染** | 跨主流浏览器（Chrome/Edge/Safari）视觉 | CSS 样式不产生严重塌陷、错位或重叠 |
| **异常容器自适应** | 填充极端尺寸的文字、图片到固定容器 | 盒子随内容扩展或打点遮蔽处理 |
| **深/浅模式主题** | 系统支持深色模式时的动态适配 | 背景色、字色不出现极低对比度的展示盲区 |
| **交互微动效反馈** | 按钮/链接的 Hover、Active、Disabled 态 | 悬停时主题色高亮；点击时有按下态；禁用时显示禁止光标 |

## 四、异常输入维度（深度边界）

> 以下 5 类异常必须在用例中逐项穷举覆盖，禁止以「异常情况」一句概括。

### A. 输入值异常

| 异常类型 | 具体示例 | 预期行为要求 |
| :--- | :--- | :--- |
| 空值 / null / 空字符串 | 必填字段留空提交 | 提示「XXX不能为空」，字段高亮，不提交请求 |
| 仅空格 | 输入框只输入若干空格 | 去空格后视为空值，与「空值」行为一致 |
| 超长字符（最大值+1） | 字段限100字，输入101字 | 前端截断或提示「最多输入100字」 |
| 特殊字符（XSS 注入类） | `<script>alert(1)</script>` | 转义存储，页面展示时不执行脚本 |
| 非预期数据类型 | 数字字段传字符串 | 返回参数格式错误，给出明确提示 |
| 极大正整数（整型溢出） | Integer.MAX_VALUE + 1 | 不因溢出变成负数，应有范围校验 |
| 极小负数 | -999999999 | 对有范围限制的字段，给出范围提示 |
| 小数/浮点数 | 数量字段输入 1.5 | 若仅支持整数，提示「请输入整数」 |
| 前后空格 | `" abc "` | 去空格后处理，或明确提示不支持 |

### B. 对象状态异常

| 异常类型 | 具体示例 | 预期行为要求 |
| :--- | :--- | :--- |
| 对象已被删除但仍操作 | 订单已删除，仍点击「编辑」 | 提示「订单不存在」，不报 500 |
| 对象处于不可操作的中间态 | 处理中的订单执行「关闭」 | 提示「当前状态不允许此操作」 |
| 并发修改同一对象 | A、B 同时打开同一订单并提交修改 | 后提交方提示「数据已被他人修改，请刷新后重试」 |
| 数据已过期但缓存未刷新 | 缓存中订单状态为「处理中」，DB 中已「完成」 | 读取时以 DB 为准 |
| 依赖对象提前消失 | 建单依赖的商品已下线 | 提示「关联商品不存在」，阻止建单 |

### C. 网络/系统异常

| 异常类型 | 具体示例 | 预期行为要求 |
| :--- | :--- | :--- |
| 接口响应超时 | 网络抖动，接口 5s 内未响应 | 有 loading 并超时后提示「网络异常，请稍后重试」 |
| 下游依赖系统返回 500 | 第三方服务崩溃 | 走降级逻辑，不将 500 直接透传给用户 |
| 网络重传导致重复提交 | 前端超时后自动重试，服务端收到 2 次相同请求 | 接口幂等性保障，DB 不产生重复记录 |
| 文件上传中断 | 上传文件到一半网络断开 | 提示「上传失败，请重新选择文件」，不产生损坏记录 |

### D. 权限与身份异常

| 异常类型 | 具体示例 | 预期行为要求 |
| :--- | :--- | :--- |
| 无权访问资源（403） | 无权限用户直接请求受保护接口 | 返回 403，不泄露资源内容 |
| Token 过期 | 登录态超过有效期 | 自动跳转登录页 |
| Token 伪造/篡改 | 手动修改 JWT 的 payload | 鉴权失败，返回 401 |
| 账号被禁用 | 运营封禁账号后该账号发起请求 | 返回 403，提示「账号已被禁用」 |
| 跨用户访问 | A 用户账号请求 B 用户的资源 | 数据隔离，返回 403 或 404 |

### E. 数据极端值

| 异常类型 | 具体示例 | 预期行为要求 |
